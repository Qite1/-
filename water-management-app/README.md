# 水利工程质量安全合规管理助手

一个**零依赖（纯 Node 内置模块）**、可离线运行的全栈 Web 应用，用于水利工程施工现场的安全隐患 AI 审核、整改意见下发与闭环台账管理。网页采用水利工程风格（堤坝 / 水流波纹 / 工程蓝配色）。

## 一、功能总览

| 角色 | 能做什么 |
|---|---|
| **管理员** | 登录系统、新增 / 删除用户账号，并赋予「施工员 / 审核员 / 管理员」身份；查看全部审核单与台账；可删除整改台账条目 |
| **施工员** | 上传施工现场照片 + 现场描述，系统（AI）按水利规范自动识别安全隐患并给出整改意见；生成 Excel 移交审核员；接收台账并落实整改、反馈闭环 |
| **审核员** | 对待审核安全单进行**确认或打回**；确认后自动形成「问题与整改意见台账」；对整改结果验收销号；可删除整改台账条目 |

**业务流程闭环：**
```
施工员上传照片 ──▶ AI 按【SL 721-2015 / SL 398-2007 / SL 714-2015 / JGJ 等】
                    识别隐患并生成整改意见（可导出 Excel）
    │
    ▼
审核员 确认 / 打回（打回则退回重新上报）
    │ 确认
    ▼
形成【问题与整改意见台账】──▶ 反馈给施工员
    │                            │
    ▼                            ▼
（逐项落实整改）         施工员：开始整改→完成整改
                                │
                                ▼
                        审核员：验收销号（闭环）
```

> 所有角色均可使用页面侧边栏的「**规范查询**」窗口，检索水利质量与安全相关标准的条款要点，供识别、整改与现场复核引用。

**首页（登录后工作台）包含：**
- 公司简介区：「湖北建投水利水电工程有限公司」的企业资质、代表性项目、团队实力、荣誉成就等（内容可在 `server/company.js` 中编辑替换）；
- 数据概览：累计隐患条目 / 重大隐患 / 较大隐患 / 待审核单等统计；
- 问题与整改概览：预览问题与整改明细，并可导出 Excel（整改台账汇总 + 问题与整改明细）。

> 提示：首页的「照片 AI 识别引擎」默认显示「✅ 已启用（真实视觉模型）」，因为服务端内置了 DeepSeek 接口配置（Key 见 `server/inspection.js` 或管理员「设置」页）。若该 Key 余额不足或模型暂不支持视觉，系统会自动回退至本地像素规则引擎，不影响巡检流程。可在「设置」中更换为自己的 Key。

## 二、快速启动

环境要求：**仅需 Node.js ≥ 16**（自带 `http/fs/zlib`），无需 npm 安装。

```bash
cd water-management-app
node server.js
```

启动后终端会打印地址与初始账号。默认监听 `http://127.0.0.1:8380`（可用环境变量 `PORT` 修改）。

### 初始演示账号
| 角色 | 账号 | 密码 |
|---|---|---|
| 管理员 | `admin` | `admin123` |
| 审核员 | `reviewer` | `review123` |
| 施工员 | `worker` | `worker123` |

> 建议登录后由管理员「新增用户」生产真实账号，并为其配置身份。

## 四、AI 识别机制（AI 优先，长期启用）

**识别方式：始终优先调用外部视觉大模型（真实 AI 识别）。**
- 服务端配置环境变量 `VISION_API_URL`、`VISION_API_KEY`（OpenAI 兼容视觉接口，OpenRouter / 智谱 / 通义 / DeepSeek / 本地 vLLM 等任选其一）后，每次上传照片由视觉模型按**内置水利规范提示词**做真实语义识别：
  ```
  VISION_API_URL=https://openrouter.ai/api/v1/chat/completions
  VISION_API_KEY=sk-xxx                          # 填入你的 Key
  VISION_MODEL=moonshotai/kimi-latest            # 选择支持视觉的模型
  ```
- **未配置 API（本机默认情况）**：系统不会静默用自研像素引擎替代，而是在上传结果中明确提示「⚠ 需配置 AI 接口」，引导管理员在服务器上设置上述环境变量后重启即可启用真实识别。

> 说明：像素引擎（`server/vision.js`）仅作为离线兜底保留，不参与默认审核流程。要获得最高识别精度，请配置可用的视觉模型 Key。
> 关于"训练"：接入的是通用视觉大模型，它已具备理解照片语义的能力，**无需提供照片训练**；只需配置模型接口 Key，并把水利规范写进提示词，模型便会按规范对每张照片做审核。

**提示词内已"学习"并贯彻以下规范要点（安全 + 质量多类型）：**
- 规范依据：《SL 398-2007》《SL 714-2015》（临边≥1.2m含挡脚板、洞口覆盖、临水救生）《SL 721-2015》（第9.0.3条个体防护）《SL 677-2014》（养护≥14d）《SL 176-2007》《GB 50204-2015》（第5.3.2条钢筋连接）《JGJ 46-2005》（三级配电两级保护）《JGJ 80-2016》（安全带高挂低用）《JGJ 130-2011》（脚手板满铺、连墙件）《GB 6067.1-2010》（吊装警戒）《SL 753-2017》（基坑支护监测）等。
- **问题类型**：区分「安全」（个人防护、临边洞口、脚手架、高处、用电、起重、动火消防、临水防汛、文明施工）与「质量」（钢筋锈蚀/连接、混凝土裂缝/养护/外观、模板支撑、支护与监测、砌体防水）。
- **三色安全帽**：模型按工程安全帽黄（工人）/红（领班/管理）/白（项目部/监理）三色分别识别，检出任一色即视为已佩戴，避免将所有人员误判为"未戴安全帽"。
- **不确定项处理**：凡模型无法从画面像素确证的结构性隐患（防护栏杆内部损伤、连墙件可靠度、基坑监测数据、隐蔽工程等），输出时置「待现场核查」并给出施工员核查要点，绝不臆断为重大。

## 五、规范查询窗口

页面左侧导航「**规范查询**」入口，全员可用，内置 20 余部水利质量与安全常用规范的**条款全文（要点版）**，并为每部规范提供可点击跳转的**在线全文 / 权威检索链接**：
- **关键词检索**：输入「临边 / 支护 / 漏电 / 救生 / 围堰」等，命中条款聚焦展示；
- **分类筛选**：按 桩基基础 / 土石方边坡 / 混凝土 / 钢筋 / 模板支撑 / 脚手架与高处作业 / 安全用电 / 起重吊装 / 防洪防汛 / 危化消防 / 质量检测 / 人员与防护 / 文明施工与环保 等 15 类；
- **内容呈现**：每条规范含 规范编号 / 名称 / 规范要点概述 / 若干条款（条款号 + 标题 + 正文 + 要点概括），以及「🔗 查看在线全文」按钮一键跳转权威检索。

> 因规范全文受版权保护，界面默认展示经整理的核心条款要点，同时以链接形式跳转权威来源获取完整条文，兼顾准确性与合规性。

## 六、Excel 递交与概览导出

**① 单条审核单 Excel（施工员递交 / 审核员下载）**
- 「安全隐患审核」表：序号 / 照片文件名 / **问题类型(安全·质量)** / 风险等级(红橙黄配色) / 隐患类型 / 隐患描述 / 规范依据 / 整改意见 / **是否待现场核实**；
- 「审核信息」表：审核单编号 / 工程名称 / 上报人员 / 审核日期 / 统计 / 状态。

**② 工作台概览 Excel（问题与整改台账导出）**
- 工作台「问题与整改概览」面板提供 `👁 预览明细` 与 `⬇ 导出概览Excel`；
- 导出文件含两张表：**整改台账汇总**（台账编号/来源单/工程/施工员/审核员/最高风险/状态/时间）与 **问题与整改明细**（每条问题的问题类型、风险、描述、规范依据、整改意见、是否待核查、核查要点）；
- 支持按当前身份导出（施工员导出自己上报的，管理员/审核员导出全部）。

该 Excel 即作为递交给审核员的正式材料；审核员确认后系统自动登记为台账并反馈给出上报的施工员，用于逐项落实整改并闭环。
