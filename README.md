# 水利工程质量安全合规管理助手（Web）

面向水利施工企业的质量安全合规管理平台，天蓝色水利工程设计风格。**前端为单页应用（HTML/CSS/JS），配套 Node.js 后端（`server/`）提供 REST API 与数据持久化、AI 代理**；前端数据通过后端共享，多人多设备可见。后端零第三方依赖、开箱即跑（详见 [server/README.md](server/README.md)）。

## 二、AI 隐患识别接口（DeepSeek 多模态）

系统默认接入 **DeepSeek 多模态模型 `deepseek-flash`**，按 **OpenAI 兼容 `/chat/completions` 视觉请求** 调用：

- **默认接口地址**：`https://api.deepseek.com`（自动追加 `/chat/completions`），默认模型 `deepseek-flash`（支持图片输入）。
- **API Key 不随代码预填**：请前往 [DeepSeek 开放平台](https://platform.deepseek.com/api_keys) 申请密钥，
  登录管理员后进入 **「AI 接口」** 页面填入并保存，页面会自动测试连通性。
- 请求携带 `Authorization: Bearer <apikey>`；现场照片经压缩后以 **Base64 data URL 内嵌于 user 消息**（DeepSeek 要求图片仅能出现在 user 消息），单次最多携带 6 张。
- **前置提示词（system）**：*"你是一名专业的水利工程质量安全合规助手，我提供几张照片，你依据水利工程安全、质量技术规范自动识别图片中的隐患并生成整改意见。"* 并在此基础上要求模型输出 **JSON**，包含：隐患标题 / 描述与规范依据 / 风险等级 / 规范条款 / 整改措施 / 是否需现场核实。
- **思考模式默认关闭**：DeepSeek 默认开启思考模式（thinking），思考内容计入 `max_tokens`，易把输出预算耗尽导致识别结果为空（`content` 为空、`finish_reason=length`）。本系统请求中显式传 `thinking: {"type":"disabled"}`；如需更细致的推理，可在「AI 接口」页面开启（会更慢、消耗更多 tokens）。若服务不识别 `thinking` 参数，系统会自动去参重试，兼容其他 OpenAI 兼容中转。
- 若使用其他 OpenAI 兼容中转服务，仅需在「AI 接口」页面将 **BaseURL** 改为对应服务地址（如 `https://你的中转域名/v1`），并调整模型名称（需支持图片输入）。
- 接口不可用（未配置、网络失败、返回异常）时，系统**自动回退到本地规则识别**并标记「需现场核实」，保证应用离线也能演示完整闭环。

### AI 质量安全助手（多轮对话 + 联网检索）

- **多轮对话**：每轮请求携带最近若干轮历史与动态刷新的台账快照（问题/状态/部位/人员统计），支持追问，如先问「当前有哪些待整改项？」再追问「其中高风险的详细说说」。
- **流式输出**：走 `stream: true` SSE 增量渲染，回答打字机式实时显示，可随时点击「⏹ 停止」保留已生成部分；流式失败自动降级非流式请求。
- **联网检索规范**：询问中包含「规范 / 标准 / 最新 / 修订 / SL / GB / JGJ」等关键词时，自动调用 **DeepSeek Search API**（`POST /v1/tools/search`）检索权威来源，把标题/摘要/链接注入上下文后结合作答，回答会注明来源；可在助手页面关闭该开关。搜索按成功请求计费（约 $0.75/千次），未命中关键词的普通提问不会产生搜索费用。
- **Markdown 渲染**：回答中的小标题、列表、表格、代码、引用、链接均结构化展示（`js/md.js` 零依赖渲染，全量 HTML 转义防注入）。
- **对话历史**：保存在浏览器 `localStorage`（键 `wm_chat_history`，上限 60 条），切换页面或重新登录不丢失，可一键清空。

## 四、本地预览

**推荐：启动内置后端**（同时托管前端静态资源与 REST API，多人共享数据）：

```bash
cd water-management-app
node server/server.js
# 然后访问 http://127.0.0.1:8123/
```

> 说明：仅用浏览器直接打开 `index.html`（`file://`）时，由于缺少后端与跨域限制，**登录与数据读写将不可用**。请务必通过后端地址 `http://127.0.0.1:8123/` 访问。
> 若只做界面静态预览，也可用任意静态服务器打开 `index.html`（此时数据不可用，AI 走本地规则回退）。

## 五、部署发布

本系统包含 Node 后端，以**进程**方式运行（Node `>=16`，零依赖），不能作为纯静态站直接托管：

```bash
cd water-management-app
node server/server.js        # 默认端口 8123（可用 PORT 环境变量覆盖）
```

部署到服务器时，可用一种进程守护方式常驻：
- 直接用 `nohup node server/server.js &`，或
- 配合 PM2 / systemd / supervisor 管理服务进程。

如需独立保存数据，请一并备份/迁移 `server/data/` 目录。若目标端口非 8123，需在页面加载前设置 `window.WM_API_BASE` 为 `http://<域名>:<端口>/api`（通常无需，前端默认同源 `/api`）。
